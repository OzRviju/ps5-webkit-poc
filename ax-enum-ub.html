IPC Accessibility Notification — Enum Range Bug

BUG: WebPageProxy::accessibilityNotification() (WebPageProxyPlayStation.cpp:125)
receives uint32_t `notification` via IPC from the WebProcess.
It casts it to AXObjectCache::AXNotification without range validation:

  static_cast<WebCore::AXObjectCache::AXNotification>(notification)

Then passes it to toAPI() (WebViewAccessibilityClient.cpp) which
has a switch() with NO default: branch — undefined behavior if the
value is out of enum range.

SAME PATTERN for:
  - accessibilityTextChange  (line 150) → AXTextChange enum
  - accessibilityLoadingEvent (line 164) → AXLoadingEvent enum

IMPACT:
  A compromised WebProcess can send arbitrary uint32 values via the
  AX IPC messages. The missing validation in UIProcess causes UB
  that could lead to info-leak or control-flow hijack via the
  uninitialized return value.

TRIGGER:
  This PoC generates rapid accessibility tree mutations via ARIA
  attribute changes, which will generate AXNotification IPC messages.
  On PS5, monitor klog for unexpected behavior when AX is enabled.

  For a direct test from a compromised WebProcess: send
  Messages::WebPageProxy::AccessibilityNotification(data, 0xDEADBEEF)
  and observe UIProcess behavior.
